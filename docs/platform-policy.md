# 科学交互：开放创作框架 3.1

这是用于引用、改编、组合和扩展的创作框架与参考范例库。已有例子不是封闭的题型目录，也不是每个知识点都必须套用的固定界面。优先复用经过检查的能力；能提高理解的新表示可以采用，先说明差异并验证，不要求用户事先替作者选方法。

## 规则分层

| 层级 | 内容 | 如何处理 |
|---|---|---|
| 必须守住 | 科学假设与边界、单位、状态约束、视觉含义、对照公平、必要可读性、验证诚实 | 不得用新颖或漂亮绕过；模型简化须明示 |
| 默认遵循 | 主要操作集中图下、短按操作空白复位、播放用固定占位符号、单个主题有清楚闭环、18px左右图标签 | 按设备和任务调整；偏离时记录理由、替代方式和验证 |
| 自由选择 | 配色、圆角、材质、布局、图形类型、局部放大、剖视、模型数量、渲染技术 | 按理解目标选择，不因范例没有就禁止 |

颜色、字体、间距可以随讲义主题变化；不要覆盖科学身份/量值字典。连续色标保留顺序和数值范围，类别色保留对象对应。主题切换只改显示，不重置模型、随机样本或进度。暖纸色只是默认主题，不是强制标准。固定值的旧作逐步适配，不宣称所有历史实例已完全换肤。

## 多模型与多表示

允许同一页出现多个模型，也允许2D与3D组合。

1. **独立模型并置**：各有状态和局部复位；为了一个讲义章节可顺序呈现，手机默认上下排。互不相关的实验不要塞入互斥页签。
2. **一个模型、多种表示**：共用同一状态源，所有图由它派生。观察变量与物理变量分开，坐标含义分别标明。
3. **多个物理模型耦合**：在作者材料中声明接口量、单位、数据方向、适用条件、时间尺度和求解顺序；反馈环须由求解器处理，不让两个滑条互相覆盖。
4. **比较不同模型**：固定同一输入、边界与尺度，标出各模型假设、近似和差异。不能假装两个模型输出天然可相加。

同页独立放置与物理耦合不是一件事。新增打包器支持隔离嵌入；不会自动把两个模型的公式连接起来。耦合任务仍需编写并核对适配器或共同控制器。

## 新形式如何进入

优先顺序：引用现有范例 → 改编或组合 → 新增表示。遇到现有方法不适用，先完成一个小而完整的样例，不无限复制变体。

在项目约定旁添加 `extension` 记录：

- `need`：读者遇到什么理解障碍。
- `reused`：复用了哪些既有方法及源路径。
- `gap`：既有方法为什么不足，不能只写“更炫”。
- `proposal`：新表示/新模型及适用边界。
- `departures`：哪些推荐做法调整，原因与替代措施。
- `checks`：科学、含义、交互、布局、宿主分别有什么证据。
- `outcome`：实验性、可复用参考、建议淘汰；新例不会自动升级为通用规范。

向用户用一段短说明解释真正的新能力和风险； routine主题/布局变化不需要新增例外报告。用户明确的普通工作授权足够执行，不把此流程变成反复审批。

## 执行流程

1. 先定学习目标、模型条件、对照基准。
2. 选表示与组合关系，列视觉字典和动作后果。
3. 写约定，明确需要继承的旧能力；没有合适方法时写扩展记录。
4. 实现可观察—可操作—看见差别—恢复基准的闭环。
5. 检查模型、实际状态、重复操作、尺寸和目标宿主；保存可重复脚本。
6. 交付成果并标真实状态；新反馈回到通用规则，不局限于改一个例子。

## 本轮确定的待办归属

| 原待定事项 | 现在的决定 |
|---|---|
| 是否继续加2D题目 | 暂停；已有13例，只有出现方法缺口才增样例 |
| 是否限制模型数量 | 不限制；按独立、同源多表示、耦合、模型比较四种关系组织 |
| 是否必须服从范例UI | 不必；分清底线和默认做法，主题自由 |
| 多例同页、重复ID冲突 | 用隔离iframe宿主容纳旧片段；新片段内部使用实例局部查询 |
| 统一宿主样式 | 提供独立页打包器与warm/paper/dark三套主题；使用者可扩展令牌 |
| 新式模型是否先获准 | 不要求常规审批；说明缺口、先做最小样例、验证后登记 |
| 扩散收支与近似误差 | 按课程目标启用，不作为所有范例的强制模块 |
| 旧例12px、控件分散 | 保留兼容来源，明确列入旧例迁移；不得用统一放大CSS制造坐标重叠 |
| 真机/Notion嵌入验收 | 保留为明确验收缺口；没有设备不能改写成通过 |

框架3.1的创作规则和接入方法已确定；不等于所有历史例子、设备和科学新模型已验收。每份交付都应分别报告：来源状态、模型检查、交互检查、布局检查、目标设备状态。
