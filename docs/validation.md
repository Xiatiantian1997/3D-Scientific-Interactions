# 验证与迁移：检查约定，也检查成品

## 实现之前

写好创作约定，先运行 `scripts/validate_contract.py`。建立输入、状态与编码字典，记录必须保留的已有能力。不要等画完才补一份永远能自证正确的约定。

## 实现之后的五组证据

| 区域 | 最少实际检查 | 常见不合格 |
|---|---|---|
| model | 手算/来源基准、干预后依赖、守恒、极限条件；示意边界 | 模型是假设却报精确配方；把原子变色当作化学反应 |
| semantics | 对初始、基准、目标、过渡、换页、换尺度状态逐个对照字典 | 同色换义；场采样点冒充原子；整片颜色暗示线缺陷 |
| interaction | 执行主要动作、来回比较、重复点击、中断和换页 | 终态标签提前出现；动画中断留下混合状态；观察改了物理模型 |
| layout | 320/360px窄屏和用户平板常用宽度；长标签与触摸命中区 | 对照在代码里但在画面下方被遮住；小图缩成不可辨认 |
| host | 当前可访问的实际宿主、页面滚动、触摸/键盘替代入口 | 用桌面模拟宽度声称真机多指验证 |

每组记录 `tested`（实际执行）、`reviewed`（源码/静态审查）或 `pending`（说明还缺什么），不合并成无依据总分。没有设备或独立学习者时明确限制。已知科学或视觉含义错误必须修复；未测宿主可作为有边界的原型交付，但不能称全面通过。

## 逐状态误读审查

- 同一显著样式在所有模式中逐一报出含义。比较实际 CSS/Canvas 色值映射，不能只检查token名称。
- 暂时遮住长解释，保留必要短图例，指出对象、基准、变化和可操作区域。
- 检查静态同色对象不动是否符合模型；动态对象的身份是否保持。
- 对三维标记核对投影、深度与遮挡，标记不能浮在结构上冒充新实体。
- 对宏观/微观核对标记单位和代表对象；不声称某个示踪点等于完整气体收支。
- 删除每个辅助元素，写出具体损失。无损失就删；结构必要的 A/B/C 或量纲不能因另一个案例字母冗余而删除。
- 换主题后重复检查；灰度或色觉差异下依然能通过结构、动作、少量标签/可读说明完成任务。不能只靠颜色标“正确/错误”。

## 比较与保留能力的回归

改版前从用户认可的产物和反馈提取清单。改版后实际执行相同任务，不只搜控件是否存在。比较基准清楚且入口就在相关图附近；镜头、尺度、对象ID、非干预变量保持一致。必要的观察变化须独立说明。

支持不同比较形式，不要求所有图都有左右两份。复杂度扩展前先确认最小“识别—操作—差别—恢复”闭环成立。新增类型不得重定义既有样式；新增动画不得破坏快速切换和观察操作。

## 检查器的明确边界

检查器发现的是声明数据中的重复语义、缺字段、无效引用、动作变化/固定重叠，以及未说明对照和保留能力。它不读取并证明渲染代码，不判断句子真假，不知道保留清单是否遗漏，也不能判断新手能否理解。`pending` 允许记录，但不是通过证据。不得把脚本成功称作完整验收。

## 跨任务迁移

用没有参与制定规则的任务检查：自由输入与派生量、符号含义、过程与构造、对照条件、主题和宿主能否分清。可用恒压/恒流、电场与势能、多物种反应、统计采样等任务，不附标准答案暗示执行者。记录失败与实际边界。

研究支持仅解释设计风险；AI自评或少量任务通过不证明广泛教学有效。
