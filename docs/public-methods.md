# 公开交互方法：从参考作品到可复用选择
研究日期：2026-10-31

后续更新：[前端交互研究](frontend-interaction.md)补充 Wodniack/JIEJOE 视频、SVG 与 CSS 透视、手势和动画性能。CVD 后续已改为逐像素深度检测，详情见 [CVD 结构](cvd-structure.md)；下文关于面片排序和“待修复”的描述属于本次初始研究记录。

本轮扩大公开资料范围，优先采用作者原文、项目官方文档和教学研究。研究对象是表达方法，不是给讲义统一套一种外观。以下采用建议是本项目的综合判断，并非各来源对本项目效果的背书。

本轮证据：阅读公开页面、文档与研究摘要；没有逐一运行全部项目，没有完成触摸屏实测或学习效果实验。先前 Anatomy 参考继续保留，但不再作为唯一结构模板。本轮未修改 CVD 演示代码；用户指出的遮挡与穿模仍待修复。

## 一、按理解困难选择方法

| 学习者的困难 | 可复用方法 | 公开参考 | 本项目采用方式与边界 |
|---|---|---|---|
| 内部被外壳挡住 | 逐层揭开、连续拆解、随时合拢 | [Bartosz：Mechanical Watch](https://ciechanow.ski/mechanical-watch/) | 先整体后局部；展开保持部件身份。教学展开不冒充实际维修路径。 |
| 看局部后不知道它在哪里 | 局部聚焦，同时保留邻近结构 | [Mol*：Managing the display](https://molstar.org/viewer-docs/managing-the-display/) | 保留少量定位环境，焦点成为旋转中心；不要把周围全删掉。借鉴选择层次，不照搬专业面板。 |
| 需要知道内部某个位置的形状 | 剖切与关联切片 | [vtk.js 官方示例](https://kitware.github.io/vtk-js/examples/) | 只有问题确实需要截面才启用；截面是观察工具，不能涂色冒充缺陷或新物质。 |
| 名称与实体对不上 | 随模型运动的标注、定位视角 | [model-viewer：Annotations](https://modelviewer.dev/examples/annotations/) | 默认少量标签，选择后揭示；标签必须指向对象。朝向判断不等于完整遮挡检测，屏幕覆盖线可能始终画在前面。 |
| 图在动却看不出过程 | 连续动画、暂停、拖回关键时刻 | [Bartosz：Mechanical Watch](https://ciechanow.ski/mechanical-watch/) | 过程连续发生，操作用于停看和探查；可以统一暂停。示意阶段与物理时间分开，不把所有机制硬接成真实轨迹。 |
| 调了数却不知谁决定谁 | 同一输入模型派生全部图文 | [Tangle](https://worrydream.com/Tangle/)、[Red Blob：Diagram structure](https://www.redblobgames.com/making-of/diagram-structure/) | 区分控制量、固定条件、状态量和输出。数值依赖本身不证明物理因果。借鉴方法，不默认引入历史库。 |
| 不知道能碰哪里、该观察什么 | 可操作对象、约束、提示与即时反馈 | [PhET 研究摘要](https://arxiv.org/abs/1306.6544) | 减少“下一步”按钮，让动作直接对应变化；不理解时先修图形反馈，不自动添加更多文字。 |
| 3D 前后关系错误、透明层混乱 | 深度检测、控制透明范围、必要时开窗 | [Three.js：Transparency](https://threejs.org/manual/pages/transparency.html) | 不透明实体优先；不能把整机半透明当成通用透视方案。几何碰撞与透明排序分别排查。 |

补充切片参考：[xeokit Section planes](https://xeokit.io/docs/terms/section-planes/)。此项作为后续阅读入口，不计入已完成交互实测。

## 二、三维首先解决空间可读性

### 先区分四种故障

| 现象 | 需要排查什么 | 不能用什么掩盖 |
|---|---|---|
| 部件实际进入另一部件内部 | 模型尺寸、间隙、接触、装配层级、动画路径 | 改颜色、整体透明 |
| 某角度远处面盖住近处面 | 渲染深度与面片排序 | 仅调整默认视角 |
| 透明壳层前后忽隐忽现 | 透明排序、深度写入、重复表面 | 不断降低透明度 |
| 重合表面闪烁 | 共面几何、深度精度、相机裁剪范围 | 加更多细节 |

现有 CVD 示例以 Canvas 按面片平均深度绘制，存在复杂交叠时排序近似的局限。后续复杂实体优先评估具有逐像素深度检测的 WebGL 渲染；引入渲染器仍不能自动修复实际几何相交、透明混合或错误的运动路径。

### 大而粗地建立结构，再缩到讲义

1. 大视图先放主要体块，建立容纳、连接、支撑关系。
2. 采用不透明材质，暂不加无助理解的螺丝、花纹和玻璃效果。
3. 检查装配、完全展开，以及各阶段的中间状态；改变相机，而不是只看推荐角度。
4. 确认必要间隙、连接点和运动包络。示意扩大间隙时说明不按比例，不能改错连接关系。
5. 加入必要的识别细节，再缩至手机和讲义实际区域；缩小后看不清就减结构或切局部。
6. 最后处理圆角、柔和阴影、层次和触摸手感。材质不能抢走主体。

### 揭示内部的选择顺序不是固定模板

- 看装配关系：优先连续展开，保留来处与归位。
- 看管路连接：先画连接和流路，隐藏妨碍阅读的外壳即可。
- 看某处截面：剖切，并让切片与整体位置对应。
- 看大量微观粒子中的局部关系：局部聚焦和邻域表示。
- 看数值变化：二维图、基准虚影和读数常比旋转模型有效。

“3D 更好”只在空间关系确实参与理解时成立。所有视图都要保留正常/变化的必要对照；切换视角不等于提供了对照。

## 三、平台应沉淀什么

建议平台分成可组合的三层，而不是把所有例子变成同一套页签：

**模型层**：对象身份、关系、条件、独立输入、派生输出；如涉及反馈，定义状态与时间推进。先确认实验边界，再确定谁能变。公式等号两边不能直接当作因果箭头。

**表达层**：同位置比较、基准虚影、局部聚焦、连续揭示、剖切、过程回放、联动读数。每个模块说明适用的理解困难和可能误导的含义。

**外观与操作层**：字号、留白、颜色、圆角、触摸命中区、相机手势、暂停和复位。换主题不改变对象身份与物理语义。毛玻璃可用于少量浮层，不覆盖需要读清的主体。

这是一种待实现的组织方式，不宣称仓库已经具备全部组件或通用引擎。

## 四、AI 创作流程补充

每次先写五行工作说明：
1. 学习者最终应看懂的一个关系。
2. 不操作时能否先辨认对象和正常状态。
3. 哪个动作能揭示关键差别，哪些条件保持不变。
4. 本次选择哪种方法，以及为什么另一种常见方法会遮挡或误导。
5. 要观察哪些中间状态，怎样证明没有丢掉原来认可的功能。

随后实现最小闭环，优先用画面解释。若需要长段说明解释一个色块或装饰线是什么，先检查它是否应该存在。

参考 PhET 的设计研究，我们采用“可操作性、约束、提示、反馈”作为审查问题；这不是声称该研究已经验证我们的具体 UI。参考 Red Blob 的数据流组织，我们让同一模型驱动画面和文字；这也不代替科学模型验证。

## 五、下一步实施与检查

优先级一：修当前 CVD 的遮挡与几何路径；保留展开、合拢、旋转、部件定位和手机阅读。先大体块检查，再决定是否迁移渲染器。不得只增加面数。

优先级二：抽出局部聚焦、基准比较与连续进度三个小模块；通过不同主题检验是否可复用，不再扩充一批只有一个图的演示。

优先级三：真机触摸、页面滚动冲突、帧率和新手理解检查。每项分别记录源码审查、桌面实测、真机实测、待验证。

视觉验收至少覆盖：初态；进度 0/25/50/75/100%；途中反向；切换目标；正侧背面与高低视角；窄屏。抽样检查不等于数学上的无碰撞保证。
